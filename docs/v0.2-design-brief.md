Upgrade TNA Gate from an authorization decision service into an enforcement mediator.
Today the system can answer:
“Is this agent allowed to perform this action?”
v0.2 must additionally answer:
“Can the protected tool actually be invoked only through TNA-controlled enforcement?”
The core security rule for v0.2 is:
A protected capability must not be directly usable by the governed agent.
The governed agent requests an action.
TNA Gate authorizes it.
TNA then exercises the approved capability through a controlled execution broker.
The agent does not receive unrestricted credentials to the protected system.


The broker is the only component permitted to invoke registered protected tools.
The broker must:
1.  receive a capability, 
2.  validate capability integrity, 
3.  verify capability has not been consumed, 
4.  re-check agent revocation, 
5.  re-check policy issuance compatibility, 
6.  verify action/tool/resource bindings, 
7.  atomically redeem the capability, 
8.  execute the registered handler, 
9.  persist execution evidence, 
10.  return a structured result.
