# TNA Gate v0.2 Threat Model

## Trust boundary

The governed agent is untrusted and may submit malformed, replayed, or adversarial requests. Gate control-plane code, its SQLite store, the capability key, the server-owned registry, and the broker are trusted for this milestone. The demo handler is trusted code that performs only a local simulated write. Direct invocation is not cryptographically prevented by the agent's possession of the process or host: the server/API deployment boundary is trusted, while OS isolation and network interception are **unimplemented**.

## Controls and limits

| Threat | v0.2 control | Status/limit |
|---|---|---|
| Direct tool invocation | No tool route; registry handler is broker-only; unknown route is 404 | Enforced at API design, not host-level isolation |
| Forged or modified capability | HMAC-SHA256 and canonical payload verification | Implemented; key custody is local env/memory |
| Replay | SQLite single-use consumption before invocation | Implemented; external side effects remain non-transactional |
| Cross-agent/tool/resource use | Principal ownership and exact field bindings | Implemented |
| Revocation or policy replacement after ALLOW | Critical state recheck immediately before redeem | Implemented |
| Expired envelope/capability/approval | Exclusive expiry checks | Implemented |
| Missing approval or budget | HOLD at authorization; no capability issuance | Implemented |
| Secret disclosure | No secret in token; absent secret broker blocks | Implemented fail-closed path |
| Unknown registry tool | Exact server registry lookup | Implemented |
| Concurrent issuance/redemption | SQLite transactions and consumed marker | Implemented and regression-tested |
| Audit tampering | Hash-chained evidence verification | Detects ordinary edits, not privileged DB rewrite |
| Handler output leakage | Return/result hash only; sanitized failure reason | Implemented for current broker |

## Revocation, expiry, and concurrency

Revocation is permanent for an agent ID. Policy replacement receives a new issuance revision and invalidates older decisions/capabilities. Envelope, approval, and capability expiry are exclusive at the boundary. Runtime and cost reservations protect authorization state but do not terminate a running process or measure actual cost. SQLite serializes the issuance and redemption critical sections; it cannot make a real external side effect atomic with evidence.

## API security boundaries

All routes require bearer authentication. Administrator, approver, and agent credentials are distinct. Vol 1 routes remain available, while capability routes fail closed when no broker is configured. `/v1/capabilities` accepts only a decision ID; `/v1/capabilities/redeem` accepts only token and exact execution bindings. There is no direct tool route. The loopback demo is not a production network boundary; TLS, operator identity, rate limits, remote evidence anchoring, and credential rotation are deployment work.

## Non-goals

This milestone does not provide OS/container sandboxing, a network proxy, DNS/rebinding or redirect enforcement, production deployment execution, real secret retrieval, KMS/HSM integration, key rotation, handler process isolation, rollback, termination, actual billing, human-attestation proof, or protection against a compromised Gate host. It also does not claim that a self-reported destination or cost proves what an external adapter actually did.
