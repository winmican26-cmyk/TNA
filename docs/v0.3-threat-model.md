# TNA Gate v0.3 Threat Model

## Scope and status

Vol 3 adds documented process isolation, application-level egress controls, and strict tool-input binding around the Vol 2 broker. The local implementation is **IMPLEMENTED**/**TESTED** only where stated below. It is not a production sandbox or a proof against a compromised host.

## Boundaries

The trusted boundary is the Gate process, its server-owned registry, capability codec, evidence store, and trusted adapters. The governed agent is untrusted and must not receive handlers, credentials, or arbitrary executable selection. The child process is less trusted than Gate, but the current runner is a process boundary with resource limits, not a kernel sandbox.

| Threat | Current result | Evidence / limitation |
|---|---|---|
| Direct tool or handler invocation | **IMPLEMENTED**, **TESTED** | Registry metadata hides handlers, `invoke` rejects, and there is no direct HTTP tool route. |
| Shell injection / arbitrary command selection | **IMPLEMENTED**, **TESTED** | Trusted adapter chooses executable; runner uses structured args and `shell:false`. |
| Workspace traversal and symlink escape | **IMPLEMENTED**, **TESTED** | Relative path validation plus workspace/cwd `realpath` containment. |
| Runaway child / output flood | **IMPLEMENTED**, **TESTED** | Timeout, output caps, bounded previews, and process-tree termination. |
| Child bypasses application egress | **NOT IMPLEMENTED** | No kernel firewall, namespace, proxy interception, or syscall policy. |
| SSRF via approved hostname or DNS rebinding | **PARTIALLY ENFORCED** | URL/host/port/private-range checks and per-redirect DNS preflight; DNS TOCTOU remains. |
| Credential leakage on redirect | **IMPLEMENTED**, **TESTED** | Cross-origin redirect strips sensitive and configured credential headers. |
| Tool-input substitution | **IMPLEMENTED**, **TESTED** | Strict schema and canonical `input_hash` are bound at issuance and redemption. |
| Revocation before execution | **IMPLEMENTED**, **TESTED** | Broker rechecks revocation immediately before consumption. |
| Exactly-once external effect | **NOT IMPLEMENTED** | SQLite consumption/evidence and an external side effect cannot commit atomically. |
| Compromised Gate host / privileged database rewrite | **NOT IMPLEMENTED** | Host, process, and operator trust are outside this milestone. |

## Evidence and state

Transitions are `REQUESTED`, `AUTHORIZED`, `CAPABILITY_ISSUED`, `STARTED`, `SUCCEEDED`, `FAILED`, `TERMINATED`, and `BLOCKED`. Isolated evidence records runner type/version, workspace identifier, network request/mode/enforcement, runtime limit, exit code, termination reason when applicable, stdout/stderr byte counts and digests, and `input_hash`. Raw output and secrets are not persisted by the broker.

`STARTED` means the single-use capability was consumed and invocation was authorized; it does not mean an external action completed. The concurrency rule is transactional: one capability is consumed once, and concurrent redeemers lose at the store boundary. Revocation and policy checks happen before consumption. The idempotency basis is single-use capability consumption plus execution evidence, not an external idempotency key. A crash after an external effect and before final evidence can leave the outcome indeterminate; replay is blocked, but exactly-once effect is **NOT IMPLEMENTED**.

Secrets are declared by tool metadata and require a `SecretBroker`; absent brokerage blocks execution. No secret is placed in capability payloads, child environment allowlists, output previews, or evidence. Real Vault/HSM delivery is **FUTURE**.
