# v0.2 implementation plan

Goal: extend the existing authorization service with short-lived authenticated capabilities, controlled demo-tool execution, and append-only execution evidence.

Baseline: Git was absent on initial inspection. Created baseline commit `4eca92790d530af73cd81a329ce8acf7085113f5`, tag `tna-gate-v0.1`; implementation branch is `tna-gate-v0.2`. The original 53 tests are permanent regression tests.

## Bounded work atoms

1. Capability core (high risk): new package and focused crypto tests only. Strict versioned payload; HMAC-SHA256; canonical encoding; conservative TTL; malformed/forged/modified/expired tokens rejected.
2. Execution mediation (high risk): new execution-broker package and broker tests only. Registry, demo tool, secret-broker interface, transactional single-use redemption, critical-state rechecks, append-only transitions, no tool output or secrets exposed.
3. API integration (high risk): API wiring, startup configuration, v0.2 HTTP tests and demo. Preserve v0.1 routes and tests. No direct tool endpoint. Existing decision and new capability/execution steps remain distinct.
4. Verification and documentation: full checks, independent read-only security review, source design preservation, proof artifacts and scoped limitations.

Implementation uses isolated agent contexts with disjoint file ownership. Each producer has at most 60 tool calls and a 30-minute timebox, with a stop/report after 3 consecutive attempts without progress. Coordinator runs deterministic checks and obtains an independent verifier verdict. Local implementation is authorized by the user's instruction; no deployment, production connection, or merge to the baseline branch is part of this work.

## Shared interfaces

Capability core exports `CapabilityCodec`, `CapabilityPayload`, and `CapabilityError`. Constructor takes a secret string (minimum 32 bytes), optional clock `() => number`, and optional TTL seconds (default 30, maximum 60). `issue(input)` returns `{token, payload}`; `verify(token)` returns parsed payload or throws. Issuance input supplies all payload fields except `version`, `issued_at`, `expires_at`, `single_use`, and `nonce`; input may supply an `expires_at` cap. Payload fields: version `1`, capability_id, execution_id, agent_id, decision_id, action, tool, resource, operation, destination (string or null), policy_hash, policy_issuance_id, issued_at, expires_at, single_use=true, nonce. Timestamps are ISO UTC strings. No credentials in payload.

Execution package exports `ExecutionBroker`, `ToolRegistry`, `createDemoRegistry`, `SecretBroker`, `SecretLease`, and `BrokerError` (numeric status). Broker constructor: `(store, codec, registry, options?)` where options contain `now?: () => number`, `secretBroker?: SecretBroker`. Methods: `issue(principal, decisionId)`, async `redeem(principal, input)`, `execution(principal, executionId)`, and `executions(principal, agentId)`. Principal is the existing agent/admin/approver type. Redeem input is a strict object `{token, tool, resource, operation, destination?}`. Capability issuance checks an existing ALLOW decision, ownership, current policy/revocation/expiry/approval state and registered tool compatibility; never issues twice for one decision. No gate decision rewriting.

`createDemoRegistry(artifactDirectory)` registers `demo.deploy.execute` with action `production.deploy`, infrastructure/write, networkRequired=false, no real credentials. It simulates deployment of a release identified by the authorized resource into the caller-provided workspace sandbox directory; never performs external network activity. Registry and handlers are trusted server implementation, never agent supplied. Only the broker has an invocation path exposed through HTTP.

API adds POST `/v1/capabilities` with `{decisionId}`, POST `/v1/capabilities/redeem`, GET `/v1/executions/:id`, GET `/v1/agents/:id/executions`. `createGateServer` takes optional third broker argument for backward compatibility. Startup uses `TNA_CAPABILITY_KEY` and registers the demo tool under `data/demo-artifacts`. Missing key prevents enabling execution. Original authorization-only integration remains usable without a broker; execution routes fail closed.

External side effects cannot be committed atomically with SQLite. Redemption and STARTED evidence must commit before invocation. A post-side-effect persistence failure must never permit replay; return an unavailable/indeterminate error and retain consumed capability and STARTED record. Document this exact boundary.
