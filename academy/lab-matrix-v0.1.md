# TNA Deployment Academy v0.1 — Lab Matrix

All 15 labs are real: each runs actual, already-accepted TNA code (Gate, Sentinel, VAD, Ledger, MCP
gateway, client store, deployment-ops, or the packaged client gateway binary) and reports real,
step-level, non-self-reported evidence. No lab accepts a learner-asserted pass/fail/score. Every lab is
deterministically verified by `tests/academy/lab-verifier.test.ts` (asserts `passed === true` and that a
synthetic zero-step result can never report `passed: true`) and by `tests/academy/lab-inventory.test.ts`
(asserts the exact lab-01…lab-15 set, no accidental gap or rename). TNA-68 ("Training Must Be Verified")
and TNA-69 ("Training Authority and Production Authority Are Separate") apply to every row below and are
not repeated per-row.

## Notes

- **Destructive lab isolation**: `lab-06` and `lab-11` are the only two labs marked destructive. Both
  require `ACADEMY_LAB_MODE=true` and confine every file operation to `academyLabWorkspaceRoot()`
  (`academy/lib/lab-paths.ts`). `tests/academy/lab-safety.test.ts` proves `../` traversal, an absolute
  path outside the workspace, and a symlink/junction escape are all rejected, and that a production data
  path is refused as a target — 0 skips.
- **Process-spawning labs** (`lab-07`, `lab-08`, `lab-10`, `lab-13`, `lab-15`) each spawn a real OS
  process (an MCP fixture, the operator CLI binary, or the packaged client gateway). None leaves an
  orphan: see `tests/academy/process-cleanup.test.ts`.
- **Non-process-spawning destructive labs**: `lab-06` and `lab-11` spawn no child process at all — pure
  in-process file/SQLite operations — verified structurally in the same process-cleanup test file (no
  `node:child_process` import in either lab's source).
